# 架构与维护

## UI 选型

Railplot 使用 Vue 3、TypeScript、Vite 和 Naive UI。表单、可搜索选择器、颜色选择器、弹窗、菜单、按钮与焦点管理交给组件库；线路与运行图仍使用 SVG。

选择 Naive UI 的依据是这个编辑器需要完整且统一的桌面编辑控件，其主题 API 能覆盖颜色、字号和尺寸。Tailwind 主要解决样式组织；搭配 Reka UI 等无样式组件也可实现相同界面，但仍需维护各控件的外观组合。当前规模使用完整组件库减少这部分工作，不额外引入第二套样式或状态框架。

这个决定的代价是额外的 JavaScript 体积和对组件库行为的依赖。迁移后的入口压缩约 180 KB gzip；PDF 引擎和中文字体仍按需加载。升级依赖时不能只检查构建，必须复测键盘选择、弹窗焦点、颜色提交与导出。主题统一在 `src/theme.ts` 配置，不覆盖 Naive UI 内部类名，也不使用私有 API。若以后主题 API 无法满足需求，应重新评估，而不是累积 CSS 补丁。

## 数据与编辑

- `model.ts` 是不依赖 Vue 和组件库的工程格式、校验、时间及坐标计算。导入的未知数据必须先校验；UI 控件的输入限制不能代替这一边界。
- `useProjectState.ts` 管理当前草稿、最近有效工程、本地保存与最多 100 个历史快照。无效草稿可撤销，但不交给绘图或持久化。它接收可替换的存储接口，以测试损坏数据和存储配额失败。
- `RailplotWorkspace.vue` 组合编辑器，处理文件打开／下载、列车增删、快捷键和面板切换。
- `TrainEditor.vue`、`NetworkGraph.vue`、`ProjectSettings.vue` 使用显式的 `v-model` 编辑各自负责的对象。字段修改同步进入共享草稿，统一由工程状态层校验和保存；不要再建立第二份工程状态。
- `CommitInput.vue` 与 `CommitColorPicker.vue` 只补充工程编辑所需的提交边界：输入和拖动过程留在局部缓冲，完成后写入工程一次。它们不重新实现控件样式和交互。

Vue 在一个更新周期内合并同步字段修改，因此一次批量操作通过整体替换草稿进入一条历史记录。图上拖动同样只在松手时提交，预览状态留在 `Diagram.vue`。不要在逐帧拖动或逐字符输入中写历史。

## 图形编辑

图形模式使用 [Vue Flow](https://vueflow.dev/guide/) 的拖拽、平移、缩放、选择和连线功能，按需加载，额外图形模块约 57 KB gzip。通用画布行为由库提供；`networkEditing.ts` 负责站位、线路列、连接去重、插站和列车引用保护，不依赖 Vue Flow。

`NetworkGraph.vue` 把工程投影为节点和连线。拖动只改临时画布状态，使用 Vue Flow 的网格吸附和节点范围限制实时约束坐标，松手后提交新工程；无效移动恢复原坐标。键盘移动同样调用领域操作。撤销／重做通过工程快照重新投影，画布视角不存入工程文件。物理连接无方向，序列化始终按站位从上到下排列，因此拖动车站越过另一站时会重新规范连接端点。

节点与连线可键盘聚焦。连线显式设置 SVG 小写 `tabindex`，避免浏览器忽略图库生成的大小写属性。弹窗缩放动画结束后调用公开的端点测量 API，防止库在动画中间态量取错误坐标。控件库或图形库升级时，这两条集成路径需回归验证。

图形编辑的线路外观与 SVG 导出共用 `railPath` 几何规则。图形库只参与编辑，不接管运行图或 PDF 渲染。

`networkGrid.ts` 统一编辑网格的坐标约定：横向每列 180 画布单位，纵向每格对应 5 个工程站位单位。车站中心相对节点原点偏移 14 单位；`NetworkGrid.vue` 使用同一偏移和 Vue Flow 的公开视口坐标绘制辅助线，缩放或平移后仍与吸附位置一致。网格只影响交互，不量化已保存的站位；插站产生的小数站位仍可正常打开。

格线按可视范围生成，主线与三列支线始终有明确落点。拖动期间显示相对原位置的格数并检查站位占用，最终仍由领域校验拒绝冲突；整个过程不写入历史。键盘方向键同样按一格移动，Shift 每次五格。领域中的精确站位不依赖网格模块。

`routeGeometry.ts` 区分分岔与汇合的转折端点，短区间限制转折长度，避免线段回折。此几何不依赖 UI，也用于导出。

## 绘图与导出

`Diagram.vue` 接收有效工程并发出选择和时刻修改事件，不负责持久化。`RouteLayer.vue` 被屏幕左栏与导出图幅共同使用，避免维护两套站位或线路画法。横向缩放只改变时间比例；站位纵坐标始终由同一个几何模型计算。

`export.ts` 克隆完整 SVG，移除编辑状态后导出。PNG 使用 Canvas；PDF 使用 jsPDF 与 svg2pdf.js，嵌入中文字体，保留矢量路径和可检索文字。不能用截图替换 PDF 流程。

## 验证

`npm test` 覆盖工程格式、时序、坐标、拖动边界、历史和保存失败。`npm run build` 检查 TypeScript 并构建；`npm run format:check` 保证统一格式。

UI 改动还需在浏览器检查以下实际路径：

1. 修改时刻，确认输入中不提交，Enter／移出焦点后重绘，一次撤销恢复。
2. 输入错误时刻，确认图表和本地有效记录未被覆盖，保存／导出不可用。
3. 下拉框使用键盘选择；Escape 先关闭下拉，再关闭弹窗；Tab 不离开弹窗。
4. 修改颜色后一次撤销；图上拖动、选择取消、横向缩放和滚动保持可用。
5. 保存工程、刷新、重新打开文件；分别下载 PNG、SVG、PDF，确认中文与线路完整。
6. 图形编辑中拖线、放站、上下支线、插站、删除、键盘移动各自可撤销；拖动预览不保存，引用中的站点不能删除。检查网格、拖动吸附、位移格数及冲突反馈，确认缩放和平移后仍对齐；检查节点圆点和端点对齐，以及新站自动纳入视野。
7. 检查桌面和窄屏截图；长时间窗口不得把分钟网格压缩到不可读。

浏览器临时文件放在忽略的 `output/` 中。涉及 PDF 改动时，另外检查 PDF 无栅格图表、文字可提取，并渲染检查中文排版。
